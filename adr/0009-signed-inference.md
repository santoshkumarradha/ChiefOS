# 0009 — Signed Inference as L2 primitive

## Context

A Chief OS that drafts emails, negotiates meetings, and composes contracts on your behalf needs to prove, on demand, that a given piece of AI-generated text was actually generated by a specific model at a specific time under specific inputs. Today, no consumer OS offers cryptographic proof of AI output provenance. Watermarking research (Anthropic, OpenAI) is statistical and fragile. The regulatory glide path (ESIGN/UETA, EU AI Act, eIDAS, court proceedings) will demand verifiable origin soon.

We already planned a Model Router as an L2 service. Steward directive 2026-04-21 promotes Provable AI from "demo flex" to a **kernel-native primitive**, provided it is cheap, non-bloated, and not memory-heavy.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| Watermarking only (statistical) | Zero signing cost | Fragile, contestable, not regulator-grade |
| Per-token signing | Finest-grain claim | Massive cost, bloat, fragility on streaming |
| **Per-inference attestation (atomic claim over prompt + output)** | Cheap (~1–2 ms overhead), small (~400 B per call), verifiable with Sigstore | Does not prove per-token correctness (only origin) |
| App-layer signing (outside kernel) | Easy to ship | Skippable — any agent could route around |
| Hardware TEE for every call (SEV-SNP / TDX) | Strongest possible | Not available on all local hardware or all cloud providers |

## Decision

Introduce a new L2 service **`chief-inference`** (subsumes the previously planned Model Router). Every model call — local or cloud — flows through it. Every completed inference emits a signed attestation (the **Signed Inference** feature) bound to (model_id, prompt_hash, output_hash, timestamp, device_id). Signatures are written to the Signed Typed Event Log (ADR-0005) as `in-toto v1` statements, verifiable via Sigstore / cosign.

## Rationale

1. **Atomic per-inference is the sweet spot.** Per-token is too much; per-session too coarse. Per-inference maps 1:1 to what auditors want: "prove this specific output came from this specific model under this specific prompt."
2. **Signing overhead is noise.** Ed25519 over a hash is ~1 ms; inference is hundreds of ms to seconds. < 1 % overhead.
3. **Storage is cheap.** ~400 B per attestation; blobs content-addressed and deduplicated.
4. **Kernel-native enforcement.** Agents call the model only via broker → `chief-inference`. A rogue agent bypassing this loses the capability to generate text.
5. **Three-tier claim model (honest framing).** Local inference = strong "generated by" claim. Cloud with provider TEE = strong co-signed claim. Cloud without TEE = "chain-of-custody" only. Verifiers see which tier they hold.
6. **Aligns with existing substrate.** Provenance Log (ADR-0005), Capability Broker (ADR-0002), Sigstore (research 2026-04-21-oss-landscape-scan) already give us the machinery.

## Attestation struct

~400 bytes per call. BLAKE3 hashes, Ed25519 signature, optional provider attestation:

```
InferenceAttestation {
  id              blake3 of this struct                  [32 B]
  model_id        e.g. "claude-sonnet-4-6"                [~32 B]
  prompt_hash     blake3(canonical prompt form)           [32 B]
  output_hash     blake3(canonical output form)           [32 B]
  timestamp       RFC3339                                 [24 B]
  device_id       pubkey hash (TPM/SE-sealed)             [32 B]
  seed            optional (for reproducibility)          [~8 B]
  temperature     optional                                [~8 B]
  top_p           optional                                [~8 B]
  provider_attest optional (cloud: SEV-SNP/TDX sig chain) [var]
  signature       Ed25519 over all above, device key      [64 B]
}
```

## Three claim tiers

| Tier | Scenario | Claim |
|---|---|---|
| 1 — Generated | Local model (llama.cpp + fastembed-rs + ort) | "Chief generated this text on device D at time T from prompt P using model M." Strong. |
| 2 — Co-signed | Cloud model with provider TEE (SEV-SNP / TDX) | "Provider X attested this was generated by model M; Chief co-signed on device D." Strong. |
| 3 — Custody | Cloud model without TEE | "Chief received this text from provider X at time T; no other party handled it." Chain-of-custody only. |

UX clearly labels which tier a given attestation holds. No implicit claims.

## Consequences

### Positive
- Every AI-generated artifact in the system has verifiable origin, free.
- Court-admissible audit trail (per ESIGN/UETA, eIDAS, EU AI Act limited-risk).
- Third-party verification via cosign without Chief OS installed.
- Anti-impersonation: forged AI text fails verification.
- Regulatory moat: nobody else offers this.
- Provenance Explorer surface gains a lock icon on every AI artifact.

### Negative / accepted costs
- Canonical-form rules for prompt and output must be stable forever (normalization: whitespace, param ordering, memory-graph URI refs).
- Device key management is critical — loss breaks verification for historical artifacts (mitigated by key-rotation provenance chain from ADR-0002).
- Cloud provider TEE availability lags; most cloud inference will be tier-3 custody at v0/v1.
- Streaming outputs sign at stream close — mid-stream tampering only detectable post-close.

## Implementation notes

- Service: Rust L2 crate `chief-inference`. Rust for memory safety + signing perf.
- Dependencies: `ed25519-dalek` or `ring` for signing; `blake3` for hashes; `serde` + `serde_cbor` for canonical bytes.
- Key material: device Ed25519 key sealed by TPM / Secure Enclave (per ADR-0002).
- Canonical prompt form (v0 proposal):
  - UTF-8 NFC normalized text.
  - Parameters (temp/top_p/seed) sorted by key, CBOR-encoded.
  - Memory-graph references resolved to `mem://...` URIs at hash time.
- Canonical output form: UTF-8 NFC text, no trailing whitespace beyond model output.
- Streaming: buffer output; sign on stream close.
- Verification CLI: `chief verify-inference <path-or-uri>` → OK + tier + chain, or NOT OK + reason.
- Public-key publication: DID Document + Sigstore Fulcio (when we stand up our CA) — decision deferred to a follow-up ADR.

## Revisit triggers

- Per-inference bloat observed > 1 % of inference latency → revisit hash algorithm or signing curve.
- Cloud provider TEE becomes broadly available → upgrade tier-3 attestations to tier-2 retroactively (impossible, but new calls can).
- Regulator demands per-token provenance → reconsider granularity (accept cost).
- Hardware key compromise → rotate via ADR-0002 ritual; all historical attestations remain verifiable under old key (linked via chain).
